DeskMind for Mac 0.4.2 fixes one problem: moving files did nothing when the Finder window was in icon view.

## Fixes

- **Moving files works when the Finder window is in icon view.** A task like "make a folder called Receipts and move receipts.csv into it" created the folder and finished with the file still where it was, whenever Finder showed the folder as icons (#67). In icon view, Finder gives each item's name in a different form than in list view, and DeskMind only read the list-view form, so it never offered the move. It now reads both. List view works as before. Checked on macOS 27 with the reporter's folder layout: icon view 3 of 3 and list view 3 of 3 through the command line, and both views through the installed app. 0.4.1 left the file in place in icon view every time. The person who reported it confirmed the fix on their Mac.

Nothing else has changed since 0.4.1. It is built from the same code as pre-release [v0.4.2-rc.1](https://github.com/deskmind-ai/deskmind/releases/tag/v0.4.2-rc.1). The models are the same, and models already downloaded are not downloaded again.

## Known

- In Notes, DeskMind can't yet select a note in the list, so tasks on a single note don't work there (deskmind#49).

## Requirements

A Mac with Apple Silicon and macOS 15 or later.

**中文说明**

DeskMind for Mac 0.4.2 修复了一个问题：Finder 窗口是图标视图时，移动文件不起作用。

**修复**
- **Finder 窗口是图标视图时，也能移动文件了。** 以前，只要 Finder 用图标显示文件夹，「新建一个『报销』文件夹，把 报销单.csv 移进去」这类任务就会建好文件夹后结束，文件还留在原处（#67）。图标视图下 Finder 给出文件名的方式和列表视图不同，DeskMind 只认列表视图的那种，所以从来不会提供「移动」。现在两种都认，列表视图下的行为不变。在 macOS 27 上按报告者的目录结构测过：命令行下图标视图 3 次、列表视图 3 次都正确，装好的 App 里两种视图也都正确；0.4.1 在图标视图下每次都没移动。报告这个问题的用户也在自己的 Mac 上确认已经修好。

除此之外与 0.4.1 相同。这一版和预发布版 [v0.4.2-rc.1](https://github.com/deskmind-ai/deskmind/releases/tag/v0.4.2-rc.1) 用的是同一份代码。模型没有变化，已经下载的模型不会重复下载。

**已知问题**
- 在「备忘录」里，DeskMind 还不能在列表中选中某条备忘录，所以针对单条备忘录的任务暂时做不了（deskmind#49）。

**系统要求**
Apple 芯片的 Mac，macOS 15 或更新版本。
