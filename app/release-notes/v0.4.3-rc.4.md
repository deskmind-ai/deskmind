**Pre-release** of 0.4.3, for testing before it becomes the latest version. 0.4.2 stays the latest until then.

## Since 0.4.2

- **Searching the web from Safari works (#73).** Before, "open Safari and search for the weather in Singapore" could type into a search box on the open page and report the task done, and "search in the smart search field" was refused. Now:
  - DeskMind offers the address bar as one action, "search in the address bar". A model checks that searching there is what you asked for before anything is typed.
  - Other text still never goes into the address bar. For example, copying a table from a page into a file does not type the table there.
- **DeskMind works in its own browser window and leaves yours alone.** For a task in Safari or Chrome, DeskMind opens a new window of its own in the background, titled "DeskMind 的窗口" at first, and works only there.
  - Windows you already had are never read, brought back from the Dock, or navigated. The same goes for any window you open while the task runs.
  - The window stays open when the task ends, so you can see the result.
  - The first time, macOS asks whether **DeskMind Hands** may control Safari. If you don't allow it, the task stops and says where to turn it on: System Settings › Privacy & Security › Automation › DeskMind Hands.
  - Firefox and Arc can't yet be given a window of DeskMind's own. A task in them stops rather than use your window.
- **If the page you mean is in your own window, DeskMind says so.** For example, "copy the parts table on this page into parts.txt" while the page is open in your window. DeskMind can't read that window, so it asks which address to open or what to search for, or it stops and says why. In this version it doesn't yet act on your answer; that comes in a later version.
- **"Done" needs something to show for it.**
  - In a browser, a model checks the page in DeskMind's window before a task is reported done. If the page can't be read, or the check gives no answer, the task stops as not confirmed.
  - When no window can be seen at all, a task is reported done only if both of these hold:
    - a model confirms the result needs no window, for example a file saved and then closed;
    - something was actually done.
  - A goal that was already true at the start also counts as done.
  - Chrome doesn't show DeskMind its pages by default. For now, browser tasks in Chrome stop as not confirmed instead of reporting done.
- **An app that isn't in front is still seen.** Before, if Safari was open but another app was in front, DeskMind could see no Safari window at all and report the task done without doing anything.
- **A locked screen stops the task.** Before, a task started while the Mac was locked could report done without doing anything. Now it stops and says the screen is locked.

## Since rc.3

New in this version:
- the browser page check before "done";
- the note when the page you mean is in your own window.

Testing rc.3 showed two problems:
- A search could be reported done without the result page being checked.
- When the page was in the user's own window, DeskMind clicked around Safari's sidebar, including the user's tab groups.

**中文说明**

0.4.3 的**预发布版**，转为正式版之前供测试。在此之前，正式版仍是 0.4.2。

**相比 0.4.2**
- **在 Safari 里搜索网页能用了（#73）。** 以前，「打开 Safari，搜索新加坡的天气」可能会把字打进当前网页自带的搜索框，然后报告完成；「在智能搜索栏里搜索」则会被拦下。现在：
  - 地址栏作为一个动作出现：「在地址栏搜索」。打字之前，先由模型确认在这里搜索正是你要的。
  - 其他内容仍然不会打进地址栏。比如把网页上的表格抄进文件，不会把表格内容打到地址栏里。
- **DeskMind 在自己的浏览器窗口里做事，不碰你的窗口。** 在 Safari 或 Chrome 里做任务时，DeskMind 会在后台新开一个自己的窗口（一开始显示「DeskMind 的窗口」），只在这个窗口里操作。
  - 你原来开着的窗口，以及任务进行中你自己新开的窗口，都不会被读取、从程序坞里弹出来或者被跳转。
  - 任务结束后这个窗口会留着，方便你看结果。
  - 第一次使用时，macOS 会问是否允许 **DeskMind Hands** 控制 Safari。如果不允许，任务会停下，并告诉你去哪里打开：系统设置 › 隐私与安全性 › 自动化 › DeskMind Hands。
  - 暂时还不能给 Firefox 和 Arc 开 DeskMind 自己的窗口。在这两个浏览器里的任务会停下，而不是用你的窗口。
- **你要处理的网页如果在你自己的窗口里，DeskMind 会说明。** 比如网页开在你的窗口里，你说「把网页上的零件表抄进 parts.txt」。DeskMind 读不了你的窗口，所以会问你要打开哪个网址、或者搜索什么，或者停下并说明原因。这一版还不会根据你的回答继续做，这一步以后的版本再做。
- **说「完成」要有依据。**
  - 在浏览器里，报告完成之前，由模型看一遍 DeskMind 窗口里的网页。读不到网页，或者判断没有给出答案，就以「无法确认」停下。
  - 一个窗口都看不到时，下面两条都满足才报告完成：
    - 模型确认这个结果本来就不需要窗口（比如文件存好后关掉了）；
    - 确实做过事。
  - 一开始就已经是你要的样子的，也算完成。
  - Chrome 默认不向 DeskMind 提供网页内容，所以目前在 Chrome 里的浏览器任务会以「无法确认」停下，而不是报告完成。
- **应用不在最前面也能看到。** 以前，Safari 开着但前面是别的应用时，DeskMind 可能一个 Safari 窗口都看不到，什么都没做就报告完成。
- **锁屏时会停下。** 以前在锁屏状态下开始的任务，可能什么都没做就报告完成。现在会停下，并说明屏幕已锁定。

**相比 rc.3**

这一版新加了两项：
- 报告完成前检查浏览器里的网页；
- 你要处理的网页在你自己的窗口里时，会说明情况。

测试 rc.3 时发现两个问题：
- 一次搜索没检查结果页就报告了完成。
- 网页在用户自己的窗口里时，DeskMind 在 Safari 侧边栏里乱点，包括用户的标签页组。
